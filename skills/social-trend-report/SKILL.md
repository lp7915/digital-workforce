# 周报生成、留档与发布

## 输入
读取当前 run_id 的 events.json、insights.md、质量报告、验收记录及项目报告模板。核对周期与数据版本一致；失败批次、质量限制和未核实信息必须随报告交付。

## 本地交付
1. 按 templates/weekly-report.md 形成 Markdown：一句话结论、周期与质量、四维洞察、事件清单、行动建议、来源与限制。
2. 每个重点结论关联 event_id 与 source_url。图表只能使用本轮数据；没有图片则省略，不虚构截图或图表来源。
3. 使用 references/report-template.html 作为最小结构生成 HTML。所有数据文本必须 HTML 转义，URL 仅允许 http/https，禁止将数据原样作为脚本或 HTML 注入。
4. 本地文件是草稿，没有托管地址不能声称网页可公网访问。

## 外部交付
1. 确认飞书工具真实可用、目标文档或目录已配置且有写权限。未配置时交付本地 Markdown 并列出阻塞项。
2. 调试期先展示报告供确认；只有已配置生产授权或本次明确授权才创建/更新飞书文档及对外发布。创建回执必须保存文档 ID/URL，发布回执必须有可核验页面 URL。
3. 发布依赖客户提供的托管接口、真实工具和凭证引用。不要猜测接口，不将密钥写进网页、文件或报告。
4. 以 run_id 关联 output-manifest.json，保存本地文件、飞书文档、网页地址及每步状态。网络超时先查目标结果，不重复新建文档或重复发布。失败与结果未知分开记录。
5. 未经授权不主动向群聊发送或向其他人分享报告。Memory 中仅沉淀确认结论及链接，不复制全量报告与中间数据。

当前初始化只提供配置及技能，不代表已启用业务调度、持久化人工审批或自动网页托管。
