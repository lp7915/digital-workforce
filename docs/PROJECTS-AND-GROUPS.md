# 项目与群聊

项目包含项目记忆、数字员工、项目群聊、成员与权限四个标签页。全局群聊和项目群聊使用同一份 groups 数据，项目内列表根据 projectId 派生。

项目员工保存员工 ID、职责及 read/write 记忆权限。加入项目不会自动加入飞书群。项目群添加机器人前校验员工已在项目中；只读员工不能执行项目记忆整理。普通 Session 始终只读挂载，不因 write 权限直接开放写入。

原有项目从群内员工初始化项目员工名单，保留原整理能力。新增项目员工默认只读。自动进群或新关联群不再把员工补入项目名单。名单外员工保留实际在群状态，但不响应项目群消息、不加载项目记忆；需显式加入项目名单后才能服务。退群保留项目员工名单与群归属，不删除项目资料。

记忆范围保持员工自身库 + 当前群所属项目全部库；私聊仅自身库。跨项目参与关系不扩大 Session 的记忆范围。变更群归属或记忆库集合后需 /new。

## 飞书事件同步

初始化、升级应用时请求订阅 im.chat.member.bot.added_v1 和 im.chat.member.bot.deleted_v1。已有应用须在飞书完成事件订阅升级，代码更新不会自动修改远端订阅。上线前需真实进退群验收；不补拉历史事件。

事件更新员工在群状态，新发现群默认不关联项目，以群 ID 显示（可从飞书选择同步名称或编辑名称）。重复/乱序事件按每群每员工时间戳去重。SDK 0.4.1 缺少公开退群回调，group-event-adapter.ts 集中扩展已有 dispatcher，共用一条 WebSocket，并以真实 SDK 调度测试保护升级兼容性。
