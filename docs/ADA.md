# ADA · 营销艺人分析师

在数字员工列表点击「初始化数字员工」，选择 ADA。已配置方舟 Key 时先核验或上传三个真实 MA Skill，再创建或复用员工并打开基础信息页；未配置 Key 时只创建配置，技能标记待初始化。重复操作保留用户身份、知识、记忆和技能启停状态，补齐配套技能。同名非模板员工不会被覆盖。

## 配置内容

- Identity：面向品牌营销、策略与商务团队的分析师，先结论后证据，明确事实、计算、推断与假设。
- Knowledge：艺人画像、内容趋势、聚合受众、品牌适配、公开合作与舆情、效果复盘；配套来源和指标口径规范。
- Rules：不编造数据与引用，不混算不同平台指标，不以相关性代替因果，不推断隐私或敏感属性，不擅自对外联络与承诺。
- Skills：从 MA 读取、绑定真实 Skill ID 和版本。ADA 使用三个技能：`ada-artist-profile`（数据核验与画像）、`ada-brand-fit`（品牌适配与对比）、`ada-campaign-review`（合作策略与复盘）。
- Memory：一个方法与模板库，包含 `playbooks/artist-analysis.md`、`templates/brief.md`、`standards/metrics.md`、`templates/evidence-register.md`、`templates/artist-report.md`。
- 环境：600 秒任务超时配置；模型沿用 MA 默认 Agent 配置。环境字段目前是工作台配置，不代表独立模型部署。
- 凭证与渠道：默认不含凭证，飞书及豆包未绑定。配置审核后可从飞书渠道页启动已有的应用创建流程。

## 执行边界

技能包源码位于项目 `skills/ada-*/SKILL.md`，已上传到 MA。服务器按当前 Key 在本地维护已初始化的技能 ID 与标签，`src/workforce/skill-catalog.ts` 仅保留历史 ADA 资源作为兼容候选，仅使用页面配置的 APIKey 按清单查询 `GET /skills/{id}`，绑定前回读技能详情并校验清单；新建 Agent 时使用 `{type:"custom",skill_id,version}` 引用，不能用本地文本冒充 Skill。原六项分析流程已迁入知识中。技能执行仍使用现有运行时工具，不会凭空增加实时数据源。已创建 MA Agent 的后续配置编辑不自动更新远端版本，需在员工页通过「MA 配置」同步。

原生标签写入尚未验证生效。目前 `ada` 标签和三个 Skill ID 由本地服务清单维护，不依赖名称或描述筛选，不拉取 MA 全量技能列表。技能内容和版本仍来自 MA，清单外的技能不能通过绑定接口新增关联；已有员工引用不受清单调整影响。

## 首次试用示例

「ADA，请帮某护肤品牌比较艺人 A 和艺人 B 的合作适配度，目标为新品认知，分析近 90 天。我会上传两份同平台数据。请先列出需要确认的问题，核对数据口径，再输出比较报告；没有证据的维度标记未知。」

预期先澄清目标人群、市场和数据来源，再执行质量检查与可比性分析。关键结论应可追溯到文件位置或来源链接；不应在没有数据时编造艺人评分。
