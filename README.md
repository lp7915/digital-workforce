# 数字员工工作台

本地运行的数字员工管理平台，连接方舟 Managed Agents（MA）与飞书，让数字员工在项目群聊中工作，并使用员工记忆和项目记忆。

## 当前能力

- **数字员工与运行任务**：配置基础信息、Identity、Knowledge、Skill、记忆、环境与凭证，接入飞书，查看任务状态。
- **项目与群聊**：项目管理记忆库和关联群聊；通过飞书 API 查询并关联群，在项目群聊中添加数字员工。群聊模块查看实际在群员工，监听 Bot 进群、退群事件同步状态。
- **MA 原生记忆**：记忆库 → 带路径的条目 → 文本内容；支持多个项目记忆库、路径树和原位编辑。群聊加载员工自身记忆及该群关联项目的记忆，私聊加载员工自身记忆。
- **飞书对话**：复用既有 Gateway/Channel 运行链路，支持卡片回复、会话和凭证管理，以及中断后的状态核验。
- **记忆整理**：支持群内 `/remember` 和后台整理入口；服务端每天北京时间 00:00 整理记忆。普通对话结束不会立即自动写回记忆。
- **ADA 场景**：提供营销领域艺人分析员工配置和三个配套 Skill：艺人画像、品牌适配、营销复盘。Skill 实际来自 MA，工作台只列出本平台的技能清单。
- **资源初始化**：在方舟 API Key 配置处核验、复用或补齐 Skill、环境、记忆库、员工 Agent/Vault/凭证，以及记忆整理 Agent。

当前项目成员管理及其记忆写入权限控制已移除。工作台仅供本机运行，尚未提供企业登录或公网访问管理。

## 启动

需要 Node.js **22.13 或以上**、npm。MA Skill 初始化还需要系统提供 `zip` 命令。

```sh
git clone https://github.com/<owner>/digital-workforce.git
cd digital-workforce
npm ci --ignore-scripts
npm start
```

打开 **http://127.0.0.1:8790**。当前工作台无需管理员令牌登录。服务固定监听本机；`WORKFORCE_PORT` 可修改端口，`WORKFORCE_DATA_DIR` 可指定数据目录。

```sh
npm run check
npm test
npm run build
```

测试主要使用模拟 MA/飞书响应及临时本地 HTTP 服务；通过测试不等于外部账户权限和资源已配置完成。构建输出位于 `dist/`。

## 配置 MA 与飞书

1. 在页面的「方舟 API Key」中保存并验证当前账户密钥。
2. 配置数字员工；ADA 的配套技能源码位于 `skills/`。
3. 使用「一键初始化 MA 资源」核验和补齐资源。**先上传或复用 Skill，再创建或更新引用 Skill 的 Agent**。初始化进度可在弹窗及任务页查看。
4. 初始化会暂停飞书 Channel；完成后重启本地服务。资源或记忆库关联发生变化后，在飞书使用 `/new` 建立新会话。
5. 从员工详情接入飞书，完成页面引导中的授权、应用配置与发布；将机器人加入群聊，并在项目中关联该群。

飞书可用性取决于当前用户权限、应用发布状态和事件订阅。Bot 进退群同步需要订阅 `im.chat.member.bot.added_v1` 与 `im.chat.member.bot.deleted_v1`。

初始化仅对明确不存在的资源进行重建；权限错误、超时或创建结果未知时不会盲目重复创建。**已删除且无备份的 MA 记忆正文不能还原，只能重建空库**。切换账户不会迁移旧 MA Session 或恢复旧账户数据。

密钥保存在本地私有配置文件，员工、项目、任务与资源关联保存于本地 SQLite。仓库不包含 API Key、飞书 App Secret、数据库、授权二维码或运行日志；克隆项目后需要独立配置。
