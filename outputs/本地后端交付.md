## 启动和数据

在项目目录运行 `npm start`，访问 http://127.0.0.1:8790 。仅绑定 127.0.0.1，不提供访问管理界面。端口用 `WORKFORCE_PORT` 指定，数据目录用 `WORKFORCE_DATA_DIR` 指定，默认 `data/workspace.db`。服务退出后数据仍保留；SQLite 使用 WAL，备份时应停止服务后复制数据库，或使用 SQLite 的备份机制。

首次连接空数据库时，从当前浏览器 `workforce.frontend.v1` 导入员工、项目、记忆及版本；原型中的假运行任务不会导入。已有数据库时以服务器为准，不会再导入或覆盖。原 localStorage 保留，旧 Gateway 数据库保持独立。

## 已实现

- 员工基础信息、身份、知识与规则、技能、记忆库与路径条目、环境、凭证引用、渠道配置和本地版本保存。
- 项目、记忆库与路径条目、群聊关联、成员权限设置保存。
- 后端拒绝非法/重复路径、缺失引用、重复群聊绑定、移除最后管理成员、无效环境配置、明文凭证和已发布版本篡改。
- 每次配置保存携带修订号；冲突返回 409，不覆盖更新。前端保存期间禁止重复修改；失败会重新读取服务器，并尽可能把未保存修改保存在 `workforce.unsaved-backup`，提示具体错误。
- 本地任务队列：提交、取消、等待/运行/完成、文本结果、每 2 秒刷新。请求 ID 去重，任务结果不能由配置保存接口覆盖。
- 任务使用提交时固定的员工配置和记忆快照；有激活版本时使用该版本配置，否则使用当前草稿。员工记忆和选中项目记忆单独挂载，不读取其他项目。运行中任务在重启后安全重新排队。

## 接口

| 方法与路径 | 内容 |
| --- | --- |
| `GET /api/workspace` | `{revision, initialized, mode, state}` |
| `PUT /api/workspace` | 请求 `{revision, state}`，事务校验并保存，返回新状态 |
| `GET /api/workspace/tasks` | 返回 `{tasks}` |
| `POST /api/workspace/tasks` | `{requestId, name, employeeId, projectId?}`，创建上下文快照任务 |
| `POST /api/workspace/tasks/:id/cancel` | JSON `{}`，取消尚未结束的任务 |

配置采用单份工作台 JSON 存储以匹配当前前端；任务独立存储。修订号为整个工作台粒度，所以不同页面修改不同项目也可能产生冲突。这是本机第一版接口，不是多用户生产环境的最终资源 API。

## 当前边界

任务的真实执行内容是确定性的上下文组装与文本产出，未调用 MA、未启动模型、未发送群聊消息。渠道、环境及凭证只保存配置/引用，没有连接外部服务。成员权限保存并校验结构，但本机操作者统一视为管理员；未实现多用户身份及读写授权。后续接 MA 时，应替换任务执行器，并验证原生 Memory 挂载与更新契约；不能将此次本地验收视为外部平台联调完成。
